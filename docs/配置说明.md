# 配置说明（瞬知 / Vivid）

这份文档回答的是：

**瞬知**（Vivid） 的关键配置都在哪里，分别控制什么。

## 配置分层

当前项目的配置可以分为四层：

### 1. 运行路径配置

控制：

- 输出目录
- 下载器路径
- `ffmpeg` 路径

关键变量：

- `VIVID_DATA_DIR`
- `VIVID_FFMPEG_BIN`
- `VIVID_BILI_SCRIPT`
- `VIVID_DOUYIN_SCRIPT`

### 2. 转录配置

控制：

- Whisper 模型
- 转录后端
- 语言
- 任务模式

说明：

- 内部 `Whisper` 转录依赖 `torch`
- 所以如果你启用内部转录，`torch` 需要可用
- 项目没有强行固定 `torch` 版本，因为正确版本通常取决于 CPU / CUDA / 平台
- 如果你是 CPU 环境，通常 `pip install -r requirements.txt` 就够
- 如果你是 GPU / CUDA 环境，建议先按官方 `PyTorch` 说明安装匹配版本的 `torch`

关键变量：

- `VIVID_DEFAULT_MODEL`
- `VIVID_TRANSCRIPTION_PRESET_ID`
- `VIVID_TRANSCRIPTION_BACKEND`
- `VIVID_TRANSCRIPTION_DEVICE`
- `VIVID_TRANSCRIPTION_TASK`
- `VIVID_TRANSCRIPTION_EXTRACT_AUDIO`
- `VIVID_TRANSCRIBE_TIMEOUT`

### 3. OCR 配置

控制：

- OCR 后端
- OpenAI 兼容视觉 API 地址
- API Key
- 模型
- Prompt
- 采样间隔

关键变量：

- `VIVID_VISION_BACKEND`
- `VIVID_VISION_API_CONFIG_ID`
- `VIVID_VISION_API_BASE`
- `VIVID_VISION_API_PATH`
- `VIVID_VISION_API_KEY`
- `VIVID_VISION_MODEL`
- `VIVID_VISION_TIMEOUT`
- `VIVID_VISION_PROMPT`
- `VIVID_VISION_SYSTEM_PROMPT`
- `VIVID_VISION_SAMPLE_MS`
- `VIVID_VISION_MIN_DURATION_MS`

### 4. 摘要配置

控制：

- 摘要模型提供商
- API Key
- 模型名称
- 摘要 prompt 模板

关键变量：

- `SILICONFLOW_API_KEY`
- `DASHSCOPE_API_KEY`
- `SILICONFLOW_BASE_URL`
- `DASHSCOPE_BASE_URL`
- `VIVID_SILICONFLOW_MODEL`
- `VIVID_DASHSCOPE_MODEL`
- `VIVID_LLM_MAX_CHARS`
- `VIVID_SUMMARY_PROMPT_ID`
- `VIVID_SUMMARY_SYSTEM_PROMPT`
- `VIVID_SUMMARY_USER_PROMPT`
- `VIVID_SUMMARY_PROMPTS_FILE`

## 最常用配置

### 输出目录

- `VIVID_DATA_DIR`

作用：

- 设置默认输出根目录

### Bilibili 会话

- `BILI_SESSDATA`

作用：

- 获取受限 Bilibili 内容时使用
- 优先尝试获取 Bilibili 官方字幕

来源优先级：

1. `-Sessdata` / `--sessdata`
2. `-NoSessdata` / `--no-sessdata`
3. `BILI_SESSDATA`

补充：

- `-Sessdata` 会覆盖环境变量里的 `BILI_SESSDATA`
- `-NoSessdata` 会显式忽略环境变量里的 `BILI_SESSDATA`

如果你不知道怎么获取：

1. 登录 `bilibili.com`
2. 按 `F12` 打开开发者工具
3. 打开 `Application` 或 `Storage`
4. 进入 `Cookies` -> `https://www.bilibili.com`
5. 复制 `SESSDATA` 的值

如果 `quickread` 返回 `error_code = "bili_sessdata_expired"`：

- 先提示用户更新 `SESSDATA`
- 用户提供了新值，就带新值重试
- 用户不提供，就改用 `--no-sessdata` 显式忽略旧会话，再继续后续媒体 / 转录 / OCR 流程

### ffmpeg

- `VIVID_FFMPEG_BIN`

作用：

- 显式指定 `ffmpeg` 路径

### 下载器路径

- `VIVID_BILI_SCRIPT`
- `VIVID_DOUYIN_SCRIPT`

作用：

- 覆盖默认下载器脚本路径
- 默认已指向内嵌下载器（`tools/bilibili/`、`tools/douyin/`）
- 一般无需修改，除非你要使用自定义下载器

## 转录配置说明

### 默认模型

- `VIVID_DEFAULT_MODEL`

可选值通常包括：

- `tiny`
- `base`
- `small`
- `medium`
- `large`

### 转录后端

- `VIVID_TRANSCRIPTION_BACKEND`

可选值：

- `internal`
- `auto`
- `ears4_api`

含义：

- `internal`
  - 只走 **瞬知**（Vivid） 内部 Whisper
- `auto`
  - 先内部，再回退 `Ears4`
- `ears4_api`
  - 直接走 `Ears4`

补充：

- 只要使用 `internal`，通常就会用到 `torch`

### 采集模式

- `VIVID_ACQUISITION_MODE`

可选值：

- `auto`
- `smart`
- `prefer_ocr`
- `force_ocr`

含义：

- `auto`
  - 正常优先转录
- `smart`
  - 智能推荐：
    - `Bilibili` 有官方字幕时优先官方字幕
    - 检测到视频有明显硬字幕时优先 OCR
    - 未检测到明显硬字幕时优先转录
    - OCR 仍保留兜底，不会丢掉硬字幕补救路径
- `prefer_ocr`
  - 视频先 OCR，再回退转录
- `force_ocr`
  - 视频只 OCR

## OCR 配置说明

### OCR 后端

- `VIVID_VISION_BACKEND`

可选值：

- `internal`
- `auto`
- `eyes_api`

含义：

- `internal`
  - 只走 **瞬知**（Vivid） 内部 OCR
- `auto`
  - 先内部，再回退 `Eyes`
- `eyes_api`
  - 直接走 `Eyes`

### OpenAI 兼容 OCR API

**瞬知**（Vivid） 当前支持标准 OpenAI 兼容视觉接口。

最常用字段：

- `VIVID_VISION_API_BASE`
- `VIVID_VISION_API_PATH`
- `VIVID_VISION_API_KEY`
- `VIVID_VISION_MODEL`
- `VIVID_VISION_PROMPT`
- `VIVID_VISION_SYSTEM_PROMPT`

### OCR 预设文件

默认位置：

- `./configs/vision/api_configs.json`
- `./configs/vision/prompts.json`

作用：

- 保存 OCR API 预设
- 保存 Prompt 预设

注意：

- 默认路径是按 **Vivid 仓库根目录** 拼出来的，不受你当前命令执行目录影响
- 只有在你显式设置 `VIVID_VISION_API_CONFIGS_FILE` 或 `VIVID_VISION_PROMPTS_FILE` 时，才会覆盖默认位置

## 摘要配置说明

### 主备提供商

默认策略：

1. `SiliconFlow`
2. `DashScope`
3. 规则摘要兜底

### 摘要 prompt 文件

默认位置：

- `./configs/summary/prompts.json`

作用：

- 保存摘要阶段的 prompt 模板
- 支持通过 `selected_id` 选择默认模板
- `user_prompt_template` 使用 `{transcript}` 作为逐字稿占位符

### 你通常只需要配什么

最常见只需要：

- `SILICONFLOW_API_KEY`
- `DASHSCOPE_API_KEY`

如果想换模型，再配：

- `VIVID_SILICONFLOW_MODEL`
- `VIVID_DASHSCOPE_MODEL`

如果想换摘要提示词，再配：

- `VIVID_SUMMARY_PROMPT_ID`
- `VIVID_SUMMARY_SYSTEM_PROMPT`
- `VIVID_SUMMARY_USER_PROMPT`

## Web UI 会改哪些配置

Web UI 当前可以直接设置：

- 当前任务输出目录
- 默认输出目录
- Whisper 模型
- 采集模式
- 转录后端
- OCR 后端
- OCR OpenAI 兼容 API 参数
- 当前任务的 `SESSDATA` / `no_sessdata` 策略

Web UI 的 `SESSDATA` 说明：

- 表单里的 `SESSDATA` 不会写入浏览器本地缓存
- 历史任务里也不会回显 `SESSDATA`
- 如果任务因 `bili_sessdata_expired` 失败，详情页会直接提供“用表单里的新 `SESSDATA` 重试”或“忽略 `SESSDATA` 继续”的动作

Web UI 保存的“默认值”主要用于：

- 便于下次继续使用
- 不替代你的 `.env`

## 兼容回退配置

如果你还保留 `Ears4` / `Eyes` 回退，可以继续配置：

- `EARS4_API`
- `EYES_API`

但要明确：

- 当前主路径已经优先在 **瞬知**（Vivid） 内部执行
- `Ears4` / `Eyes` 只是回退

## 推荐最小配置

对多数用户，最小配置通常是：

- `SILICONFLOW_API_KEY`
- `DASHSCOPE_API_KEY`
- `VIVID_DATA_DIR`
- `BILI_SESSDATA`（如果你需要受限 Bilibili 内容）

其余大多可以先用默认值。
